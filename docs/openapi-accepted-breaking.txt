# Breaking changes to the HTTP API that were reviewed and accepted (#197).
# The 'Schema and API compatibility' CI job passes this file to 'oasdiff breaking --err-ignore'.
# Each line: <METHOD> <path> <change, as oasdiff reports it>. Keep a comment saying why.
#
# #200: audit event types became x-extensible-enum instead of a closed enum, so adding a type
# (as every new capability does) is no longer a breaking change. A client must tolerate unknown
# event types; the set of values a client could receive is unchanged by this switch.
GET /api/v1/audit removed the enum constraint from the `events/items/eventType` response property for the response status `200`
GET /api/v1/audit/{id} removed the enum constraint from the `eventType` response property for the response status `200`
GET /api/v1/trails/{id}/audit removed the enum constraint from the `items/eventType` response property for the response status `200`
GET /api/v2/trails/{id}/audit removed the enum constraint from the `items/eventType` response property for the response status `200`
#
# #250: the /api/v1 twins are deprecated in favour of /api/v2, so v2 now validates its input as v1
# always has. Each bound below is the one the v1 endpoint already enforced; a client that worked
# against v1 is unaffected.
POST /api/v2/flows the `description` request property's maxLength was set to `2048`
POST /api/v2/flows the `name` request property's maxLength was set to `255`
POST /api/v2/trails the `gitAuthorEmail` request property's maxLength was set to `255`
POST /api/v2/trails the `gitAuthor` request property's minLength was set to `1`
POST /api/v2/trails added the pattern `^[^\s@]+@[^\s@]+\.[^\s@.]+$` to the request property `gitAuthorEmail`
POST /api/v2/trails/{trailId}/artifacts the `imageName` request property's minLength was set to `1`
POST /api/v2/trails/{trailId}/artifacts the `imageTag` request property's minLength was set to `1`
POST /api/v2/trails/{trailId}/artifacts the `sha256Digest` request property's minLength was set to `1`
POST /api/v2/trails/{trailId}/artifacts added the pattern `sha256:[a-fA-F0-9]{64}` to the request property `sha256Digest`
