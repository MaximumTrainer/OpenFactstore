Get Started

Up and running in under five minutes with Docker Compose.

Prerequisites

Make sure you have the following installed before proceeding.

☕ Java 21 Eclipse Temurin recommended
🟢 Node.js 20 With npm included
🐳 Docker Docker Desktop or Engine + Compose
📦 Git To clone the repository

Quick Start (Docker Compose)

The fastest way to run OpenFactstore is with Docker Compose, which starts all services with a single command.

# 1. Clone the repository
git clone https://github.com/MaximumTrainer/OpenFactstore.git
cd OpenFactstore

# 2. Once: generate the session secret and a bootstrap admin key (written to .env)
scripts/bootstrap-env.sh

# 3. Start all services
docker compose up -d --build

# 4. Check services are running
docker compose ps

Authentication is enforced: every API request needs Authorization: Bearer <key>. The bootstrap admin key is in .env as SECURITY_BOOTSTRAP_API_KEY.

Once running, the following services are available:

Service URL Description
Command API http://localhost:8080 Command service: every write, and reads; also serves the web UI
Query API http://localhost:8081 Query service: read-only, projected from events over RabbitMQ
RabbitMQ http://localhost:15672 Event bus management UI (credentials from .env)
Swagger UI http://localhost:8080/swagger-ui.html Interactive API documentation
Grafana http://localhost:3000 Compliance dashboards (credentials from .env)
Prometheus http://localhost:9090 Metrics collection

Manual Setup (Development)

To run the backend and frontend separately for development:

Backend

cd backend
./gradlew bootRun       # Starts on http://localhost:8080

Frontend

cd frontend
npm ci
npm run dev             # Starts on http://localhost:5173

Your First Compliance Trail

Walk through a complete compliance lifecycle using the REST API.

1

Create a Flow

A Flow is a template that defines the required compliance checks for a type of release.

export BASE_URL=http://localhost:8080
export FACTSTORE_TOKEN="$(grep '^SECURITY_BOOTSTRAP_API_KEY=' .env | cut -d= -f2-)"

FLOW_ID=$(curl -s -X POST "$BASE_URL/api/v2/flows" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "standard-release",
    "description": "Standard production release checks",
    "requiredAttestationTypes": ["security-scan", "code-review", "qa-signoff"]
  }' | jq -r .id)
2

Start a Trail

A Trail is a per-release evidence collection; report the artifact (e.g., a container image) it built by digest.

TRAIL_ID=$(curl -s -X POST "$BASE_URL/api/v2/trails" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{
    \"flowId\": \"$FLOW_ID\",
    \"gitCommitSha\": \"abc123def456\",
    \"gitBranch\": \"main\",
    \"gitAuthor\": \"alice\",
    \"gitAuthorEmail\": \"alice@example.com\"
  }" | jq -r .id)

DIGEST="sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
curl -s -X POST "$BASE_URL/api/v2/trails/$TRAIL_ID/artifacts" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{
    \"imageName\": \"my-service\",
    \"imageTag\": \"1.4.2\",
    \"sha256Digest\": \"$DIGEST\",
    \"reportedBy\": \"ci-pipeline\"
  }" | jq .
3

Record an Attestation

Attestations are individual evidence records. Record your security scan result:

curl -s -X POST "$BASE_URL/api/v2/trails/$TRAIL_ID/attestations" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "security-scan",
    "status": "PASSED",
    "details": "Trivy scan: 0 critical, 2 medium (accepted)"
  }' | jq .
4

Check Compliance

Evaluate whether the trail satisfies all flow requirements and is cleared for deployment:

curl -s -X POST "$BASE_URL/api/v1/assert" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{ \"flowId\": \"$FLOW_ID\", \"sha256Digest\": \"$DIGEST\" }" | jq .

A type the server cannot evaluate, like security-scan here, is recorded as you sent it and labelled selfAsserted. For junit, snyk, sonar and jira the status comes from the uploaded report instead; see the user guide's Who decides pass or fail.

When every required attestation type has a PASSED attestation, the response shows "status": "COMPLIANT" and the artifact is cleared for deployment; otherwise NON_COMPLIANT with the missing and failed types.

5

Evaluate the Deployment Gate

Use the deployment gate to get a binary deploy/block decision:

curl -s -X POST "$BASE_URL/api/v1/gate/evaluate" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{ \"artifactSha256\": \"$DIGEST\" }" | jq .
ℹ️
For the complete API reference including all request/response schemas, see the API Docs page or visit http://localhost:8080/swagger-ui.html when the server is running.

Dry-run Mode

Any write operation can be tested without persisting data by adding the X-Factstore-Dry-Run: true header. The API will validate the request and simulate the result without making any changes: 

curl -s -X POST "$BASE_URL/api/v2/trails" \
  -H "Authorization: Bearer $FACTSTORE_TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-Factstore-Dry-Run: true" \
  -d "{ \"flowId\": \"$FLOW_ID\", \"gitAuthor\": \"alice\", \"gitAuthorEmail\": \"alice@example.com\" }" | jq .

Configuration Reference

All runtime settings are configured via environment variables. Here are the key options for a production deployment.

Environment Variables

Variable Default Description
SPRING_DATASOURCE_URL H2 in-memory JDBC URL for PostgreSQL, e.g. jdbc:postgresql://db:5432/factstore
SPRING_DATASOURCE_USERNAME factstore Database username
SPRING_DATASOURCE_PASSWORD none Database password
SECURITY_ENFORCE_AUTH false Set to true to require API key or JWT on all endpoints
SCM_ENCRYPTION_KEY none (required outside the dev profile) Base64 of exactly 32 random bytes (openssl rand -base64 32), the AES key for SCM tokens at rest
FACTSTORE_EVENTS_PUBLISHER logging Event bus: logging | rabbitmq | inmemory | none
FACTSTORE_CQRS_ROLE none CQRS deployment: command (write) or query (read-only)
SPRING_RABBITMQ_HOST localhost RabbitMQ hostname (only used when FACTSTORE_EVENTS_PUBLISHER=rabbitmq)
OPA_MODE embedded OPA policy mode: embedded (built-in evaluator) or external
OPA_URL none URL of external OPA server when OPA_MODE=external
SERVER_PORT 8080 HTTP port the backend listens on

Production Docker Compose example

A minimal production-ready compose file with PostgreSQL, RabbitMQ, and authentication enabled:

# docker-compose.prod.yml
services:
  factstore:
    image: ghcr.io/maximumtrainer/openfactstore:latest
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL:     jdbc:postgresql://postgres:5432/factstore
      SPRING_DATASOURCE_USERNAME: factstore
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD}
      SECURITY_ENFORCE_AUTH:      "true"
      SCM_ENCRYPTION_KEY: ${SCM_ENCRYPTION_KEY}
      FACTSTORE_EVENTS_PUBLISHER: rabbitmq
      SPRING_RABBITMQ_HOST:       rabbitmq
    depends_on:
      postgres:
        condition: service_healthy
      rabbitmq:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 15s
      timeout: 5s
      retries: 5

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB:       factstore
      POSTGRES_USER:     factstore
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "factstore"]
      interval: 10s
      retries: 5

  rabbitmq:
    image: rabbitmq:3-management-alpine
    healthcheck:
      test: ["CMD", "rabbitmq-diagnostics", "ping"]
      interval: 10s
      retries: 5

volumes:
  pgdata:

CLI configuration

The factstore CLI stores its configuration in ~/.factstore.yaml. Run factstore configure to set it interactively, or create the file manually:

# ~/.factstore.yaml
host:        https://factstore.example.com
token:       fs_pat_your_api_key_here
query_host:  https://factstore-query.example.com  # CQRS read replica (optional)

All CLI settings can also be provided as environment variables:

FACTSTORE_HOST=https://factstore.example.com \
FACTSTORE_TOKEN=fs_pat_... \
factstore attest generic --type unit-tests --status PASSED --trail-id <trail-id>
✅
Use SECURITY_ENFORCE_AUTH=true and rotate API keys regularly in production. Each CI pipeline should use a dedicated SERVICE_ACCOUNT API key with least-privilege scoping.
